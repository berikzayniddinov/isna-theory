# 122. PostgreSQL визуально: где что находится физически

## Зачем это знать

Начнём с физики: где реально стоит база данных. Что за железо, что в памяти, что на диске. Только потом — как оно работает.

## 1. Физический сервер: что стоит в дата-центре

Самое базовое — БД это программа на **физическом сервере** (или виртуалке, K8s pod'e). Один сервер выглядит примерно так:

```
        ┌─────────────────────────────────────────────┐
        │           СЕРВЕР (1U / 2U rack)             │
        │                                             │
        │   ┌───────────────────────────────────┐     │
        │   │           CPU (Intel / AMD)       │     │
        │   │   8-64 ядер                        │     │
        │   │   выполняет весь код               │     │
        │   └───────────────────────────────────┘     │
        │                                             │
        │   ┌───────────────────────────────────┐     │
        │   │            RAM 16-128 GB          │     │
        │   │   быстрая память                  │     │
        │   │   хранит горячие данные           │     │
        │   │   (кэши, buffers, процессы)       │     │
        │   └───────────────────────────────────┘     │
        │                                             │
        │   ┌───────────────────────────────────┐     │
        │   │        DISK (SSD/NVMe/HDD)        │     │
        │   │   500 GB - 10 TB                  │     │
        │   │   хранит все данные постоянно     │     │
        │   │   выживает при выключении         │     │
        │   └───────────────────────────────────┘     │
        │                                             │
        │   ┌───────────────────────────────────┐     │
        │   │        NETWORK (1-100 Gbit)       │     │
        │   │   принимает запросы клиентов      │     │
        │   └───────────────────────────────────┘     │
        │                                             │
        └─────────────────────────────────────────────┘
                        │
                        │  подключён к сети
                        │
                        ▼
                     Клиенты
                (веб-серверы, приложения)
```

**Скорости** (важно понимать разницу):

```
CPU регистры        ~1 нс              (1 наносекунда)
CPU L1 cache        ~2 нс              
CPU L2 cache        ~5 нс              
CPU L3 cache        ~15 нс             
RAM                 ~100 нс            
NVMe SSD            ~100 000 нс        (в 1000 раз медленнее RAM)
SATA SSD            ~500 000 нс        (в 5000 раз медленнее)
HDD                 ~10 000 000 нс     (в 100 000 раз медленнее!)
Сеть в датацентре   ~500 000 нс        
```

Отсюда — БД **всегда** старается работать с RAM. Диск — только если данных нет в RAM.

## 2. Где физически живёт БД на этом сервере

БД — это **один или несколько процессов** в операционной системе + **файлы на диске**.

```
        СЕРВЕР
        ┌─────────────────────────────────────────────┐
        │                                             │
        │   RAM (16 GB)                               │
        │   ┌─────────────────────────────────────┐   │
        │   │                                     │   │
        │   │  ┌──────────────────────┐           │   │
        │   │  │ Процесс PostgreSQL   │           │   │
        │   │  │  - Shared Buffers   │  ← кэш    │   │
        │   │  │    (4 GB)           │            │   │
        │   │  │  - Backend процессы │            │   │
        │   │  │  - WAL Buffers      │            │   │
        │   │  └──────────────────────┘           │   │
        │   │                                     │   │
        │   │  ┌──────────────────────┐           │   │
        │   │  │ OS (Linux)           │           │   │
        │   │  │  - kernel            │           │   │
        │   │  │  - page cache        │  ← ещё   │   │
        │   │  │    (10 GB)           │  кэш     │   │
        │   │  └──────────────────────┘           │   │
        │   │                                     │   │
        │   └─────────────────────────────────────┘   │
        │                     │                       │
        │                     │  когда данных         │
        │                     │  нет в RAM            │
        │                     ▼                       │
        │   DISK (SSD/HDD)                            │
        │   ┌─────────────────────────────────────┐   │
        │   │                                     │   │
        │   │  /var/lib/postgresql/data/          │   │
        │   │    ├── base/       ← таблицы       │   │
        │   │    ├── pg_wal/     ← журнал        │   │
        │   │    ├── global/     ← служебное     │   │
        │   │    └── ...                          │   │
        │   │                                     │   │
        │   └─────────────────────────────────────┘   │
        │                                             │
        └─────────────────────────────────────────────┘
```

Два места где живёт БД:
- **RAM** — процессы + кэши (быстрый доступ, но пропадает при выключении).
- **DISK** — файлы (медленно, но данные не теряются).

## 3. Что физически лежит на диске

Если зайти в директорию БД на сервере — увидишь такую структуру файлов:

```
/var/lib/postgresql/data/
│
├── base/                       ← ТУТ ЛЕЖАТ ВСЕ ТАБЛИЦЫ
│   │
│   ├── 1/                      ← база 'template1'
│   │   └── (файлы)
│   │
│   ├── 13012/                  ← база 'postgres'  
│   │   └── (файлы)
│   │
│   └── 16384/                  ← НАША база 'myapp'
│       │
│       ├── 16385               ← файл таблицы 'orders' (250 MB)
│       ├── 16385_fsm           ← карта свободного места
│       ├── 16385_vm            ← карта видимости
│       │
│       ├── 16386               ← файл таблицы 'users' (80 MB)  
│       ├── 16386_fsm
│       ├── 16386_vm
│       │
│       ├── 16387               ← индекс orders_pkey (30 MB)
│       ├── 16388               ← индекс orders_user_id (25 MB)
│       │
│       └── ...                 ← другие таблицы и индексы
│
├── pg_wal/                     ← ЖУРНАЛ ИЗМЕНЕНИЙ (WAL)
│   │                             критичен для durability
│   ├── 000000010000000000000001    ← 16 MB файл
│   ├── 000000010000000000000002    ← 16 MB файл  
│   ├── 000000010000000000000003    ← 16 MB файл
│   └── ...
│
├── global/                     ← глобальные объекты (роли, tablespaces)
│   └── pg_control              ← control file
│
├── pg_tblspc/                  ← симлинки на tablespaces
├── pg_stat/                    ← runtime statistics
├── pg_notify/                  ← LISTEN/NOTIFY
│
├── postgresql.conf             ← главный конфиг
├── pg_hba.conf                 ← кто может подключаться
└── PG_VERSION                  ← "15" (версия)
```

**Главное**:
- Каждая БД — **отдельная поддиректория** в `base/` (например `16384/`).
- Каждая таблица — **отдельный файл** в этой поддиректории (например `16385`).
- Каждый индекс — **отдельный файл**.
- **WAL** (журнал) — отдельная директория `pg_wal/`.

## 4. Как найти файл конкретной таблицы

```sql
SELECT pg_relation_filepath('orders');
-- Вернёт: base/16384/16385
```

Проверяем на сервере:

```bash
$ ls -lh /var/lib/postgresql/data/base/16384/16385
-rw------- postgres postgres 250M ... 16385
```

Это и есть **вся твоя таблица orders** — 250 MB в одном файле.

Если таблица больше 1 GB — будет несколько файлов: `16385`, `16385.1`, `16385.2` и т.д. Каждый до 1 GB.

## 5. Что внутри файла таблицы

Файл `16385` (таблица orders) внутри разбит на **страницы по 8 KB**:

```
   Файл 16385 (250 MB = 32 000 страниц):
   
   Байт 0                                          Байт 262 144 000
    │                                                       │
    ▼                                                       ▼
   ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
   │page 0│page 1│page 2│page 3│page 4│page 5│ ...  │page N│
   │ 8 KB │ 8 KB │ 8 KB │ 8 KB │ 8 KB │ 8 KB │      │ 8 KB │
   └──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘
```

**Одна страница** — минимальная единица чтения. Читаем страницу целиком, даже если нужна одна строка.

Внутри одной 8 KB страницы:

```
   Страница (8 KB = 8192 байта):
   
   Байт 0                                                Байт 8191
    │                                                        │
    ▼                                                        ▼
   ┌──────────────────────────────────────────────────────────┐
   │  Header (24 байта)                                       │
   │  ├─ версия страницы                                      │
   │  ├─ где начинаются данные                                │
   │  └─ checksum                                             │
   ├──────────────────────────────────────────────────────────┤
   │  Указатели на строки:                                    │
   │  [1] → строка на offset 8144                             │
   │  [2] → строка на offset 8080                             │
   │  [3] → строка на offset 8000                             │
   │  ...                                                     │
   ├──────────────────────────────────────────────────────────┤
   │                                                          │
   │              СВОБОДНОЕ МЕСТО                             │
   │       (для новых строк при INSERT)                       │
   │                                                          │
   ├──────────────────────────────────────────────────────────┤
   │  Строка 3: id=42, name='Иван', ...                       │
   │  Строка 2: id=43, name='Пётр', ...                       │
   │  Строка 1: id=44, name='Мария', ...                      │
   └──────────────────────────────────────────────────────────┘
```

- **Сверху** — заголовок и указатели (растут вниз).
- **Снизу** — сами строки (растут вверх).
- **Посередине** — свободное место.

Когда посередине встречаются — страница полная, новые строки идут в следующую страницу.

## 6. Что в RAM (в памяти)

Когда PostgreSQL работает, в RAM живёт:

```
   RAM (16 GB)
   ┌──────────────────────────────────────────────────────┐
   │                                                      │
   │  1. Shared Buffers (4 GB)  ← кэш страниц PostgreSQL │
   │  ┌────┬────┬────┬────┬────┬────┬────┬────┐          │
   │  │page│page│page│page│page│page│... │... │          │
   │  │ 0  │ 4  │ 12 │ 87 │203 │892 │    │    │          │
   │  └────┴────┴────┴────┴────┴────┴────┴────┘          │
   │  ← копии страниц из файлов, чтоб не читать диск     │
   │                                                      │
   │  2. Процессы PostgreSQL                              │
   │  ┌─────────────────┐  ← главный процесс             │
   │  │ postmaster      │                                 │
   │  └─────────────────┘                                 │
   │                                                      │
   │  ┌────────┐ ┌────────┐ ┌────────┐                    │
   │  │backend │ │backend │ │backend │  ← процесс на     │
   │  │  #1    │ │  #2    │ │  #3    │    каждого        │
   │  │ ~10 MB │ │ ~10 MB │ │ ~10 MB │    клиента        │
   │  └────────┘ └────────┘ └────────┘                    │
   │                                                      │
   │  ┌──────────────┐ ┌──────────────┐                   │
   │  │ background   │ │ WAL writer   │  ← служебные     │
   │  │ writer       │ │              │                   │
   │  └──────────────┘ └──────────────┘                   │
   │                                                      │
   │  3. WAL Buffers (16 MB)  ← буфер для журнала        │
   │  ┌───────────────────────────────┐                   │
   │  │ WAL записи ждут flush на диск │                   │
   │  └───────────────────────────────┘                   │
   │                                                      │
   │  ────────────────────────────────                    │
   │                                                      │
   │  4. OS Page Cache (Linux, ~10 GB)                    │
   │  ┌────┬────┬────┬────┬────┬────┬────┐               │
   │  │    │    │    │    │    │    │... │               │
   │  └────┴────┴────┴────┴────┴────┴────┘               │
   │  ← ещё один кэш, для всех файлов                     │
   │                                                      │
   └──────────────────────────────────────────────────────┘
```

**Два уровня кэша**:
1. **Shared Buffers** — PostgreSQL кэш (специально для PostgreSQL страниц).
2. **OS Page Cache** — Linux кэш (для любых файлов).

Одна страница может быть **и там, и там** одновременно. Это называется **double buffering**.

## 8. Как всё связано (простая версия)

Когда приложение делает `SELECT`:

```
   1. Клиент (Java app) → TCP → сервер БД
   
   2. Сервер: backend процесс получает запрос
   
   3. Backend: нужна страница таблицы orders
      │
      ▼
   4. Смотрю в Shared Buffers (RAM):
      ├─ Есть? → БЕРУ! (быстро, ~1 микросекунда)
      └─ Нет? → иду ниже
                   │
                   ▼
   5. Смотрю в OS Page Cache (RAM):
      ├─ Есть? → БЕРУ! (быстро, ~5 микросекунд)
      └─ Нет? → иду на диск
                   │
                   ▼
   6. Читаю с диска (SSD ~100 микросекунд, HDD ~5 миллисекунд):
      /var/lib/postgresql/data/base/16384/16385
      offset = page_number * 8192
      читаю 8 KB
      │
      ▼
   7. Кладу в OS Cache → в Shared Buffers → возвращаю данные
   
   8. Backend → TCP → клиент
```

## Ключевые моменты запомнить

**Физически БД это**:
- Программа на сервере (много процессов).
- Файлы на диске (папка `/var/lib/postgresql/data/`).
- Кэши в RAM (Shared Buffers + OS Page Cache).

**Каждая таблица**:
- Один или несколько файлов на диске.
- Разбита на страницы по 8 KB.
- В каждой странице — строки (tuples) + служебная информация.

**Работает всегда через RAM**:
- Читает страницу с диска в память (Shared Buffers).
- Дальше работает с копией в памяти.
- Изменения тоже в памяти (dirty pages).
- Периодически записывает обратно на диск.

**WAL** (журнал) — отдельные файлы в `pg_wal/`:
- Каждое изменение сначала пишется в WAL.
- Потом уже в основные файлы таблиц.
- Защищает от потери данных при сбое.

**Скорости критично важны**:
- RAM в 1000-100 000 раз быстрее диска.
- Поэтому кэши — всё.
- Cache hit rate 99%+ — здоровая БД.
