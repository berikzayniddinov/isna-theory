# 125. Kubernetes визуально: где что находится физически

## 1. Главная схема — Kubernetes кластер

**K8s кластер = несколько серверов работающих вместе**.

Два вида серверов (nodes):
- **Control Plane** (мастер) — "мозг" кластера, управляет.
- **Worker Nodes** — где реально запускаются приложения (pods).

```
                    ┌────────────────────────┐
```

## 3. Что такое Namespace

**Namespace = "папка" внутри кластера** для изоляции ресурсов.

```
    K8s Cluster
    ┌──────────────────────────────────────────────────┐
    │                                                  │
    │  Namespace: kube-system                          │
    │  ┌────────────────────────────────┐              │
    │  │  системные компоненты K8s      │              │
    │  │  - CoreDNS                     │              │
    │  │  - kube-proxy                  │              │
    │  │  - metrics-server              │              │
    │  └────────────────────────────────┘              │
    │                                                  │
    │  Namespace: tax-report  ← наши сервисы           │
    │  ┌────────────────────────────────────────────┐  │
    │  │  Deployment: isna-tax-rep                  │  │
    │  │  Deployment: isna-tax-rep-100              │  │
    │  │  Deployment: isna-tax-rep-328              │  │
    │  │  Deployment: isna-tax-rep-report           │  │
    │  │  ... (54 сервиса)                          │  │
    │  │                                            │  │
    │  │  Service: isna-tax-rep-service             │  │
    │  │  ConfigMap: app-config                     │  │
    │  │  Secret: db-credentials                    │  │
    │  └────────────────────────────────────────────┘  │
    │                                                  │
    │  Namespace: monitoring                           │
    │  ┌────────────────────────────────┐              │
    │  │  - Prometheus                  │              │
    │  │  - Grafana                     │              │
    │  └────────────────────────────────┘              │
    │                                                  │
    │  Namespace: ingress-nginx                        │
    │  ┌────────────────────────────────┐              │
    │  │  - Ingress controller          │              │
    │  └────────────────────────────────┘              │
    │                                                  │
    └──────────────────────────────────────────────────┘
    
    Namespace изолирует:
    - Секреты (secret одного namespace не видит другой)

    - Ресурсы (можно ограничить CPU/RAM)
    
    Обычно один namespace = один проект.
```

## Что запомнить

**K8s = кластер из нескольких серверов**:
- **Control Plane** (master) — управляет.
- **Worker Nodes** — запускают приложения.

**Control Plane** содержит:
- **API Server** — принимает команды (kubectl).
- **Scheduler** — выбирает node для pod.
- **Controller Manager** — следит что всё работает.
- **etcd** — БД со всем состоянием кластера.

**Worker Node** содержит:
- **kubelet** — агент, запускает pods.
- **containerd** — контейнерный runtime.
- **Pods** — запущенные контейнеры.

**Где что хранится**:
- **etcd** (`/var/lib/etcd/`) — весь state кластера.
- **containerd** (`/var/lib/containerd/`) — кэш images.
- **kubelet** (`/var/lib/kubelet/pods/`) — runtime данные pods.
- **PersistentVolumes** — данные приложений (БД файлы и т.д.).

**Namespace** — "папка" для изоляции ресурсов (обычно один на проект).

**Три главных ресурса**:
- **Deployment** — что запускать (image, replicas).
- **Pod** — запущенный экземпляр.
- **Service** — стабильный адрес для группы pods.

**Трафик приходит через**:
`DNS → Ingress → Service → Pod`

**Общение между сервисами** — через DNS имена:
- `http://service-name:port` (внутри namespace)
- `http://service.namespace.svc.cluster.local:port` (между namespaces)

**Отказоустойчивость**:
