# 124. Build и Deploy визуально: полный путь от кода до production

## 1. Главная схема — путь от разработчика до production

```
    ┌─────────────────┐
    │   Developer     │
    │  (пишет код)    │
    └────────┬────────┘
             │
             │ git push
             ▼
    ┌─────────────────┐
    │   Git repo      │
    │  (GitLab/GitHub)│
    │                 │
    │  весь код +     │
    │  история        │
    └────────┬────────┘
             │
             │ trigger: push в main
             ▼
    ┌─────────────────────────────────┐
    │   CI/CD Pipeline                │
    │  (GitLab CI / Jenkins / GH Act.)│
    │                                 │
    │  1. Скачивает код               │
    │  2. Собирает (gradle build)     │
    │  3. Запускает тесты             │
    │  4. Собирает Docker image       │
    │  5. Пушит в Registry            │
    │  6. Деплоит в K8s               │
    └────────┬────────────────────────┘
             │
       ┌─────┴──────┐
       │            │
       ▼            ▼
    ┌────────┐  ┌─────────────┐
    │ NEXUS  │  │  Docker     │
    │        │  │  Registry   │
    │ JAR /  │  │             │
    │ WAR    │  │  Docker     │
    │ файлы  │  │  images     │
    └────────┘  └──────┬──────┘
                       │
                       │ K8s pulls image
                       ▼
    ┌───────────────────────────────────┐
    │        Kubernetes cluster         │
    │                                   │
    │   ┌────────┬────────┬────────┐    │
    │   │ Pod 1  │ Pod 2  │ Pod 3  │    │
    │   │(myapp) │(myapp) │(myapp) │    │
    │   └────────┴────────┴────────┘    │
    │                                   │
    │  Production!                      │
    └───────────────────────────────────┘
```


## 2. Что происходит во время BUILD

**Запуск**: `gradle build` (или `mvn package`).

```
    Ваш код (исходники):
    
    ┌──────────────────────────────────────┐
    │  src/main/java/                      │
    │    ├── MyApp.java                    │
    │    ├── UserService.java              │
    │    ├── OrderController.java          │
    │    └── ...                           │
    │                                      │
    │  src/main/resources/                 │
    │    ├── application.yml               │
    │    └── static/                       │
    │                                      │
    │  src/test/java/                      │
    │    └── тесты                         │
    │                                      │
    │  build.gradle                        │
    └──────────────────┬───────────────────┘
                       │
                       │ gradle build
                       │
                       ▼
        ┌──────────────────────────────┐
        │  Шаг 1: Компиляция           │
        │  javac запускает             │
        │                              │
        │  .java → .class (bytecode)   │
        └──────────────┬───────────────┘
                       │
                       ▼
        ┌──────────────────────────────┐
        │  Шаг 2: Скачивание deps      │
        │                              │
        │  Из Maven Central / Nexus:   │
        │  - spring-boot-*.jar         │
        │  - hibernate-*.jar           │
        │  - jackson-*.jar             │
        │  - и ещё ~40 JAR файлов      │
        │                              │
        │  Складывает в ~/.gradle/     │
        └──────────────┬───────────────┘
                       │
                       ▼
        ┌──────────────────────────────┐
        │  Шаг 3: Тесты                │
        │                              │
        │  Запускает JUnit             │
        │  ✓ все прошли — идём дальше  │
        │  ✗ хоть один failed — стоп   │
        └──────────────┬───────────────┘
                       │
                       ▼
        ┌──────────────────────────────┐
        │  Шаг 4: Упаковка в JAR       │
        │                              │
        │  Собирает всё в один файл:   │
        │  - .class файлы твои         │
        │  - все зависимости (~40 JAR) │
        │  - resources                 │
        │  - манифест                  │
        │                              │
        │  Итог: myapp-1.0.jar (~50MB) │
        └──────────────┬───────────────┘
                       │
                       ▼
        ┌──────────────────────────────┐
        │  Результат в build/libs/     │
        │                              │
        │  myapp-1.0.0.jar             │
        │  ← это готовое приложение!   │
        │  ← можно запустить:          │
        │    java -jar myapp-1.0.0.jar │
        └──────────────────────────────┘
```

**Что внутри JAR файла** (это просто ZIP):

```
    myapp-1.0.0.jar
    │
    ├── META-INF/
    │   └── MANIFEST.MF        ← метаданные, main class
    │
    ├── com/mycompany/
    │   ├── MyApp.class        ← твой код (bytecode)
    │   ├── UserService.class
    │   └── ...
    │
    ├── application.yml        ← resources
    │
    └── BOOT-INF/lib/          ← все зависимости
        ├── spring-boot-3.2.jar
        ├── hibernate-6.4.jar
        ├── jackson-2.15.jar
        └── ... 40 файлов
    
    Всего ~50 MB
```

## 4. Docker Registry — что там хранится

**Docker Registry = склад Docker images**.

```
    ┌────────────────────────────────────────────┐
    │            DOCKER REGISTRY                 │
    │      (Nexus / Harbor / Docker Hub /        │
    │       AWS ECR / GCR)                       │
    │                                            │
    │  Хранит Docker images:                     │
    │                                            │
    │  ┌──────────────────────────────────────┐  │
    │  │  myapp:1.0.0                         │  │
    │  │  myapp:1.0.1                         │  │
    │  │  myapp:latest                        │  │
    │  │                                      │  │
    │  │  myapp:v2.0.0                        │  │
    │  └──────────────────────────────────────┘  │
    │                                            │
    │  Каждый image = набор layers               │
    │                                            │
    └────────────────────────────────────────────┘
```

**Что такое Docker image**:

```
    Docker image = много слоёв (layers)
    
    ┌───────────────────────────────────────┐
    │  Слой 1: OS база (Alpine Linux)       │  ← ~5 MB
    ├───────────────────────────────────────┤
    │  Слой 2: OpenJDK 21                   │  ← ~200 MB
    ├───────────────────────────────────────┤
    │  Слой 3: рабочая директория /app      │  ← пустой
    ├───────────────────────────────────────┤
    │  Слой 4: копия myapp.jar              │  ← ~50 MB
    ├───────────────────────────────────────┤
    │  Метаданные:                          │
    │  - CMD ["java", "-jar", "myapp.jar"]  │
    │  - EXPOSE 8080                        │
    │  - ENV ...                            │
    └───────────────────────────────────────┘
    
    Итого: ~255 MB
    
    ⚠ Layers переиспользуются между images!
    Если у 10 images общая OS Alpine → она хранится
    только 1 раз (экономия места).
```

**Как создаётся image** (Dockerfile):

```
    Dockerfile (инструкции как собирать):
    
    ┌────────────────────────────────────────┐
    │  FROM openjdk:21-alpine    ← база     │
    │                                        │
    │  WORKDIR /app              ← папка    │
    │                                        │
    │  COPY myapp.jar .          ← копия    │
    │                                        │
    │  EXPOSE 8080               ← порт     │
    │                                        │
    │  CMD ["java","-jar","myapp.jar"]      │
    └───────────────────┬────────────────────┘
                        │
                        │ docker build .
                        ▼
                ┌───────────────┐
                │ Docker image  │
                │ (готов к      │
                │  запуску)     │
                └───────────────┘
```

**Как деплоится image в Registry**:

```
    CI сервер                     Docker Registry
    ┌──────────────┐              ┌──────────────┐
    │              │              │              │
    │  1. build:   │              │              │
    │  docker      │              │              │
    │  build -t    │              │              │
    │  myapp:1.0.0 │              │              │
    │              │              │              │
    │  2. push:    │              │              │
    │  docker push │─────────────▶│  сохраняет   │
    │  registry/   │              │  image       │
    │  myapp:1.0.0 │              │  на диск     │
    │              │              │              │
    └──────────────┘              └──────────────┘
```

## 6. Rolling Update — деплой без даунтайма

**Как обновляется приложение с 1.0 на 1.1 без остановки**:

```
    До деплоя: работают 3 pod'а версии 1.0.0
    
    ┌──────────┐┌──────────┐┌──────────┐
    │ Pod 1    ││ Pod 2    ││ Pod 3    │
    │  v1.0.0  ││  v1.0.0  ││  v1.0.0  │
    └──────────┘└──────────┘└──────────┘
    
    ────────────────────────────────────────────
    
    Шаг 1: создаётся новый pod с v1.1.0
    
    ┌──────────┐┌──────────┐┌──────────┐┌──────────┐
    │ Pod 1    ││ Pod 2    ││ Pod 3    ││ Pod 4    │
    │  v1.0.0  ││  v1.0.0  ││  v1.0.0  ││  v1.1.0  │
    └──────────┘└──────────┘└──────────┘└──────────┘
                                        ↑ starting
    
    Ждём пока pod 4 готов (health check)
    
    ────────────────────────────────────────────
    
    Шаг 2: убивается один старый pod
    
    ┌──────────┐            ┌──────────┐┌──────────┐
    │ Pod 1    │            │ Pod 3    ││ Pod 4    │
    │  v1.0.0  │            │  v1.0.0  ││  v1.1.0  │
    └──────────┘            └──────────┘└──────────┘
                  ↑ убит
    
    ────────────────────────────────────────────
    
    Шаг 3: создаётся ещё pod с v1.1.0
    
    ┌──────────┐┌──────────┐┌──────────┐┌──────────┐
    │ Pod 1    ││ Pod 5    ││ Pod 3    ││ Pod 4    │
    │  v1.0.0  ││  v1.1.0  ││  v1.0.0  ││  v1.1.0  │
    └──────────┘└──────────┘└──────────┘└──────────┘
                 ↑ starting
    
    ────────────────────────────────────────────
    
    ... и так далее пока все не станут v1.1.0
    
    ────────────────────────────────────────────
    
    Итог: все 3 pod'а версии 1.1.0
    
    ┌──────────┐┌──────────┐┌──────────┐
    │ Pod 4    ││ Pod 5    ││ Pod 6    │
    │  v1.1.0  ││  v1.1.0  ││  v1.1.0  │
    └──────────┘└──────────┘└──────────┘
    
    Всё время работал минимум 2 pod'а — сервис не падал.
```

## Что запомнить

**Путь кода до production**:
1. Developer пишет код → git push
2. CI запускается автоматически
3. **Build**: скачивает deps → компилирует → тесты → упаковывает в JAR
4. **Docker build**: JAR + OS + JDK = Docker image
5. **Push**: image в Docker Registry
6. **Deploy**: K8s скачивает image, запускает pods
7. **Rolling update**: постепенно заменяет старые pods

**Где что хранится**:
- **Git** — код + история.
- **Nexus** — JAR файлы (артефакты).
- **Docker Registry** — Docker images (JAR + OS + JDK).
- **Kubernetes** — running containers (Pods).

**Что такое JAR**:
- Обычный ZIP файл.
- Внутри: твой код (.class) + все зависимости + resources + манифест.
- Можно запустить: `java -jar myapp.jar`.

**Что такое Docker image**:
- Набор слоёв.
- Обычно: OS + JDK + твой JAR.
- Слои переиспользуются между images (экономия места).

**Что такое Pod в K8s**:
- Запущенный Docker container.
- В production обычно несколько pod'ов одного приложения (для отказоустойчивости).

**Rolling Update**:
- K8s создаёт новые pod'ы с новой версией.
- Ждёт пока они станут healthy.
- Убивает старые pod'ы.
- Сервис не останавливается никогда.
