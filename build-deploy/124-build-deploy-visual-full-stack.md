# 124. Build и Deploy визуально: реальный pipeline ISNA tax-rep

## Про проект

**isna-tax-rep** — приложение отчётности КНП (Кабинет налогоплательщика Казахстана).

- **~54 микросервиса** (модули gradle): `isna-tax-rep`, `isna-tax-rep-100`, `isna-tax-rep-110`, `-200`, `-328`, `-report`, `-sync`, `-fo`, `-integration`, `-liquibase`, `-nz-001`, `-nz-007` и т.д.
- **Java 11** (большая часть) + **Java 21** (isna-tax-rep-report и другие).
- **Gradle 6.9.4** + плагин **jib** (собирает Docker images без Docker daemon).
- **CI**: GitLab CI.
- **Kubernetes namespace**: `tax-report`.

            ▼

    │           GitLab CI Pipeline запускается           │
    └────────────────────────┬───────────────────────────┘
                             │
                             ▼
    ┌────────────────────────────────────────────────────┐
    │  Stage: test_preprod                               │
    │                                                    │
    │  Для каждого из 54 модулей:                        │
    │  cd isna-tax-rep-N                                 │
    │  gradle test                                       │
    │                                                    │
    │  ✗ хоть один упал → pipeline красный, стоп         │
    └────────────────────────┬───────────────────────────┘
                             │
                             ▼
    ┌────────────────────────────────────────────────────┐
    │  Stage: build_preprod                              │
    │                                                    │
    │  export docker_registry=test-nexus.kgd.gov.kz      │
    │  docker login -u $PREPROD_USER -p $PREPROD_PASS    │
    │                                                    │
    │  для каждого из 54 сервисов:                       │
    │    cd $SERVICE                                     │
    │    gradle bootJar jibDockerBuild                   │

## 7. Как pod физически берёт image из Nexus

**Что такое K8s Node**: это физический сервер (или VM) в кластере. На нём запускаются pods.

**На каждой node работает**:
- **kubelet** — агент K8s, следит за pods.
- **containerd** — запускает контейнеры (Docker-подобное).
- **Диск** — где хранятся скачанные images.

**Пошагово что происходит после `kubectl set image`**:

### Шаг 1: kubectl обновляет Deployment

```
    CI сервер
    ┌──────────────────────────────┐
    │  выполняет команду:          │
    │                              │
    │  kubectl set image \         │
    │    deployment/isna-tax-rep-  │
    │    328 \                     │
    │    ...=registry/isna-tax-    │
    │    rep-328:abc123 -n tax-    │
    │    report                    │
    └──────────────┬───────────────┘
                   │
                   │ HTTPS
                   ▼
    ┌──────────────────────────────┐
    │  K8s API Server              │
    │  (в кластере, "мозг")        │
    │                              │
    │  Обновляет Deployment:       │
    │  image: xyz789 → abc123      │
    └──────────────┬───────────────┘
                   │
                   ▼
    ┌──────────────────────────────┐
    │  Deployment Controller видит │
    │  изменение → нужно создать   │
    │  новый Pod с новым image     │
    └──────────────────────────────┘
```


### Шаг 2: K8s выбирает node и создаёт Pod

```
    K8s Scheduler
    ┌──────────────────────────────┐
    │  Смотрит все nodes в         │
    │  кластере:                   │
    │                              │
    │  ┌────────┐┌────────┐        │
    │  │Node 1  ││Node 2  │        │
    │  │занята  ││свободна│ ← ok!  │
    │  │много   ││        │        │
    │  └────────┘└────────┘        │
    │                              │
    │  Выбирает Node 2             │
    └──────────────┬───────────────┘
                   │
                   │ создаёт Pod
                   │ на Node 2
                   ▼
    ┌──────────────────────────────┐
    │  Node 2                      │
    │                              │
    │  Pod создан (пока пустой,    │
    │  container ещё не запущен)   │
    │                              │
    │  Спецификация Pod'а:         │
    │  image: registry.1sc.kz/     │
    │    isna-tax-rep-328:abc123   │
    └──────────────────────────────┘
```


### Шаг 3: kubelet на node запрашивает image

```
    Node 2 (физический сервер)
    
    ┌────────────────────────────────────────┐
    │                                        │
    │  kubelet видит новый Pod               │
    │  "нужен image isna-tax-rep-328:abc123" │
    │                                        │
    │  Смотрит в свой диск:                  │
    │                                        │
    │  /var/lib/containerd/                  │
    │                                        │
    │  ├── image xyz789 (старая) ✓ есть      │
    │  └── image abc123 (новая) ✗ нет!       │
    │                                        │
    │  → нужно скачать из Nexus              │
    │                                        │
    └────────────────┬───────────────────────┘
                     │
                     │ HTTPS запрос
                     ▼
```


### Шаг 4: Аутентификация в Nexus

```
    Node 2 (kubelet)              Nexus
    ┌──────────────┐            ┌──────────────┐
    │              │            │              │
    │  Login       │            │  registry.   │
    │  запрос:     │            │  1sc.kz      │
    │              │            │              │
    │  user: ...   │───────────▶│              │
    │  pass: ...   │            │  проверяет   │
    │              │            │  credentials │
    │              │◀───────────│              │
    │  Token       │            │              │
    │  получен     │            │              │
    └──────────────┘            └──────────────┘
    
    ⚠ Credentials хранятся на node как K8s Secret
      (imagePullSecrets в spec Pod'а)
```


### Шаг 5: Скачивание manifest (список слоёв)

```
    Node 2 (kubelet)              Nexus
    ┌──────────────┐            ┌──────────────┐
    │              │            │              │
    │  GET         │───────────▶│              │
    │  manifest    │            │              │
    │  для         │◀───────────│  возвращает  │
    │  abc123      │            │  manifest    │
    │              │            │              │
    └──────────────┘            └──────────────┘
    
    Manifest — это JSON со списком layers:
    
    ┌──────────────────────────────────────┐
    │  {                                   │
    │    "layers": [                       │
    │      {                               │
    │        "digest": "sha256:aaa...",    │
    │        "size": 5000000     ← 5 MB    │
    │      },                              │
    │      {                               │
    │        "digest": "sha256:bbb...",    │
    │        "size": 200000000  ← 200 MB   │
    │      },                              │
    │      {                               │
    │        "digest": "sha256:ccc...",    │
    │        "size": 60000000   ← 60 MB    │
    │      }                               │
    │    ]                                 │
    │  }                                   │
    └──────────────────────────────────────┘
    
    ⚠ Docker image = набор layers (слоёв).
    Каждый слой — просто архив с файлами.
```


### Шаг 6: Проверка каких layers уже есть

```
    kubelet проверяет каждый layer:
    
    ┌───────────────────────────────────────────┐
    │  Layer aaa (Alpine Linux, 5 MB)           │
    │  /var/lib/containerd/layers/aaa/          │
    │  ✓ ЕСТЬ (из image xyz789 — та же база)    │
    │  → пропускаем, качать не нужно            │
    ├───────────────────────────────────────────┤
    │  Layer bbb (OpenJDK 11, 200 MB)           │
    │  /var/lib/containerd/layers/bbb/          │
    │  ✓ ЕСТЬ (та же JDK база)                  │
    │  → пропускаем                             │
    ├───────────────────────────────────────────┤
    │  Layer ccc (наш JAR, 60 MB)               │
    │  /var/lib/containerd/layers/ccc/          │
    │  ✗ НЕТ (это новая версия!)                │
    │  → нужно скачать                          │
    └───────────────────────────────────────────┘
    
    Вот почему layers — гениальная идея:
    - Общие части (OS, JDK) переиспользуются.
    - Качаем только изменения.
```


### Шаг 7: Скачивание недостающих layers

```
    Node 2                    Nexus
    ┌──────────────┐        ┌──────────────┐
    │              │        │              │
    │  GET layer   │───────▶│              │
    │  ccc         │        │              │
    │              │◀───────│  60 MB       │
    │              │        │  архив       │
    │              │        │              │
    │  распаковка  │        │              │
    │      │       │        │              │
    │      ▼       │        │              │

### Шаг 8: Сборка "файловой системы" для container

```
    kubelet собирает слои вместе для запуска:

    │  Layer 1: Alpine Linux              │
    │  /bin /usr /lib /etc ...            │
    ├─────────────────────────────────────┤
    │  Layer 2: OpenJDK 11                │
    │  /usr/lib/jvm/ ...                  │
    │  (наложен поверх Alpine)            │
    ├─────────────────────────────────────┤
    │  Layer 3: наш JAR                   │
    │  /app/isna-tax-rep-328.jar          │
    │  (наложен поверх)                   │
    └─────────────────────────────────────┘
              ▼
    Итоговая файловая система:
    ┌─────────────────────────────────────┐
    │  /bin /usr /lib /etc  ← из Alpine   │

    │  /app/isna-tax-rep-328.jar  ← наш   │
    └─────────────────────────────────────┘
    
    Это виртуальная FS только для этого container.
```

    ┌──────────────┐

    ┌──────────────┐

    │                                │    │
    │  (7) GET missing layers ───────┼───┐│
    │                                │   ││
    │  (8) собирает FS               │   ││
    │                                │   ││
    │  (9) запускает container       │   ││
    │      java -jar ...             │   ││
    │                                │   ││
    │  (10) Pod Running              │   ││

                            │  registry.     │

```

**Время**:
- Первый раз (layers ещё нет на node): 30 секунд - 2 минуты.
- Второй раз (только новый JAR layer 60 MB): 5-10 секунд.
- Если тот же image повторно: мгновенно (уже локально).

## Что запомнить

**Проект isna-tax-rep = ~54 микросервиса** (модули gradle) в одном git-репо.

**Три окружения = три разных Nexus + три K8s**:
- dev → `registry.1sc.kz`
- preprod → `test-nexus.kgd.gov.kz`
- prod → `nexus.kgd.gov.kz`

**Два разных GitLab сервера**:
- `gitlab.1sc.kz` — dev/release (разработка).
- `gitlab.kgd.gov.kz` — только master (у клиента).

**14 стадий CI pipeline**:
- mr_gate → test → build → deploy для каждого окружения
- e2e_gate между preprod и prod (обязательный)

**Build через Jib**:
- `gradle bootJar jibDockerBuild` — собирает Docker image БЕЗ Docker daemon.
- Каждый image имеет 2 тега: `:<git_sha>` и `:latest`.

**Deploy через `kubectl set image`**:
- Не через Helm или манифесты.
- Просто меняет image в существующем Deployment.
- K8s делает rolling update автоматически.

**Namespace = `tax-report`** — все 54 сервиса в одном namespace K8s.

**Путь: dev → release → master**:
- Обычный flow: разработка в feature ветке → MR в release → тестирование → мерж в master → prod.
