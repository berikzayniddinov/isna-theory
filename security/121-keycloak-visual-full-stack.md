## Что где находится

**User (пользователь)**
- Просто человек с браузером или мобильным приложением.

**Frontend**
- SPA (React/Angular) или мобильное приложение.
- Хранит access token в JS memory.
- Хранит refresh token в httpOnly cookie.

**Backend API (resource server)**
- Наше приложение (Spring Boot).
- НЕ хранит токены — проверяет каждый входящий JWT.
- Ходит в Keycloak один раз при старте — забирает public key (JWKS).

**Keycloak** — весь цилиндр:

- **HTTP endpoints** — API через которое работают все клиенты (`/auth`, `/token`, `/jwks`, etc).

- **Realm** — изолированное пространство. Внутри realm лежат:
  - **Users** — сами пользователи + credentials.
  - **Clients** — зарегистрированные приложения (frontend, backend, mobile).
  - **Roles** — роли.
  - **Sessions** — кто сейчас залогинен и с какого устройства.

- **Token Signer** — приватный ключ (только внутри Keycloak) + публичный (раздаётся всем через /jwks).

- **База данных Keycloak** — своя (обычно PostgreSQL). Хранит всё выше.

**Внешние источники** (опционально):
- **LDAP/AD** — корпоративные пользователи.
- **Google/Facebook** — social login.
- **Kalkan ЭЦП** — электронная подпись (Казахстан).

## Как идёт запрос

**Первый раз (login)**:

```
   1. User → Frontend
   2. Frontend → Keycloak (login page)
   3. User вводит пароль
   4. Keycloak: проверяет и выдаёт JWT
   5. Frontend получил токен, сохранил
   6. Frontend → Backend API (Authorization: Bearer <jwt>)
   7. Backend: проверяет подпись JWT
      - Один раз забрал public key из /jwks
      - Проверяет локально
   8. Backend возвращает данные
```

**Следующие запросы (уже с токеном)**:

```
   1. Frontend → Backend API (Authorization: Bearer <jwt>)
   2. Backend: проверяет JWT (локально, без похода в Keycloak)
   3. Backend возвращает данные
   
   ← Keycloak в этом не участвует!
```

## Как работает ЭЦП (Казахстан)

```
    ┌──────────────────┐        ┌───────────────────┐
    │   User           │        │   NCALayer        │
    │  (у него         │        │   (плагин на      │
    │   USB-токен      │        │    компе user'а)  │
    │   с ЭЦП)         │        │                   │
    └────────┬─────────┘        └───────┬───────────┘
             │                          │
             │                          │
             │  подключение             │
             │  USB-токена              │
             ▼                          │
    ┌──────────────────┐                │
    │   Browser        │                │
    │                  │                │
    │  Frontend просит │                │
    │  подписать       │◄───────────────┘
    │                  │
    └────────┬─────────┘
             │
             │  подписанные данные
             │  + X.509 сертификат
             ▼
    ┌──────────────────┐
    │    Keycloak      │
    │                  │
    │  проверяет:      │
    │  - подпись       │
    │  - цепочку       │
    │    доверия       │
    │  - не отозван?   │
    │                  │
    │  извлекает ИИН   │
    │  из сертификата  │
    │                  │
    │  выдаёт JWT      │
    └──────────────────┘
```

**Простыми словами**:
1. У пользователя физический USB-токен с приватным ключом.
2. NCALayer (программа) читает токен, подписывает данные.
3. Keycloak получает подписанные данные + сертификат.
4. Проверяет что подпись валидна и сертификат действительный.
5. Извлекает ИИН из сертификата, использует как identity.
6. Выдаёт JWT токен.

## Что такое JWT (простыми словами)

**JWT = три части через точку**:

```
   xxxxx.yyyyy.zzzzz
   
   ┌──────────────────────────────────────────────┐
   │  1. Header (что это)                         │
   │     {                                        │
   │       "alg": "RS256"  ← алгоритм подписи     │
   │     }                                        │
   ├──────────────────────────────────────────────┤
   │  2. Payload (данные)                         │
   │     {                                        │
   │       "sub": "ivan-uuid",  ← кто             │
   │       "email": "ivan@ex.com",                │
   │       "roles": ["ADMIN"],                    │
   │       "exp": 1712345678  ← когда истечёт     │
   │     }                                        │
   ├──────────────────────────────────────────────┤
   │  3. Signature (подпись)                      │
   │     RSA_sign(private_key, header + payload)  │
   │     ← защита от подделки                     │
   └──────────────────────────────────────────────┘
```

**Проверка на backend**:
1. Разбираем на 3 части.
2. Берём public key (из /jwks Keycloak, кэшированный).
3. Проверяем подпись — совпадает? Значит не подделан.
4. Проверяем exp — не истёк?
5. Читаем payload — знаем кто user и его роли.
6. Если валиден → пропускаем запрос.

**Почему это круто**:
- Backend НЕ ходит в Keycloak на каждый запрос.
- JWT содержит всё что нужно.
- Проверка локальная (быстро, ~1 мс).

## Что запомнить

**Keycloak = центральный сервер identity**:
- Один на всю компанию.
- Все приложения проверяют auth через него.

**Три типа участников (OAuth 2.0)**:
1. **User** — человек.
2. **Client** (frontend, backend, mobile) — приложение которое хочет доступ.
3. **Authorization Server** (Keycloak) — выдаёт токены.
4. **Resource Server** (backend API) — проверяет токены.

**Внутри Keycloak — иерархия**:
- **Realm** = отдельное пространство (обычно одно на проект).
- Внутри realm: **Users** + **Clients** + **Roles** + **Sessions**.

**JWT**:
- Самодостаточный токен (не нужно ходить в БД).
- Подписан приватным ключом Keycloak.
- Проверяется публичным ключом (JWKS).
- Живёт короткое время (~15 минут).
- Обновляется через refresh token.

**ЭЦП (Казахстан)**:
- Пользователь имеет физический USB-токен.
- Программа NCALayer подписывает данные.
- Keycloak проверяет подпись и извлекает ИИН.
