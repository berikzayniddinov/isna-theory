# 121. Keycloak визуально: полная физическая архитектура

## 1. Главная схема — где что стоит

```
    ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
    │  User 1  │   │  User 2  │   │  User 3  │   │  User N  │
    │ (browser)│   │ (browser)│   │ (mobile) │   │ (browser)│
    └────┬─────┘   └────┬─────┘   └────┬─────┘   └────┬─────┘
         │              │              │              │
         └──────────────┴──────┬───────┴──────────────┘
                               │
                               │ HTTPS
                               ▼
                   ┌───────────────────────┐
                   │      Frontend         │
                   │  (React / Angular)    │
                   └───────────┬───────────┘
                               │
                  ┌────────────┴─────────────┐
                  │                          │
                  ▼                          ▼
       ┌──────────────────┐        ┌──────────────────┐
       │    KEYCLOAK      │◄───────│   Backend API    │
       │  (auth server)   │        │ (resource server)│
       │                  │        │                  │
       │  выдаёт токены   │        │  проверяет токены│
       └──────────────────┘        └──────────────────┘
```


## 2. HTTP запрос — как выглядит физически

**Один HTTP запрос от Frontend к Backend с токеном**:

```
    Frontend делает fetch:
    
    GET https://api.myapp.com/orders
    Authorization: Bearer eyJhbGciOiJSUzI1NiJ9.eyJzdWIi...
    Content-Type: application/json
                            │
                            │ HTTPS через сеть
                            ▼
    Backend получает:
    
    ┌────────────────────────────────────────────┐
    │  HTTP Request                              │
    │                                            │
    │  Method: GET                               │
    │  URL: /orders                              │
    │                                            │
    │  Headers:                                  │
    │  ┌──────────────────────────────────────┐  │
    │  │ Authorization: Bearer <JWT токен>    │  │  ← ГЛАВНОЕ!
    │  │ Content-Type: application/json       │  │
    │  │ User-Agent: Chrome...                │  │
    │  └──────────────────────────────────────┘  │
    │                                            │
    │  Body: (пустой для GET)                    │
    └────────────────────────────────────────────┘
                            │
                            ▼
    Backend обрабатывает:
    
    ┌────────────────────────────────────────────┐
    │  1. Извлечь токен из Authorization header  │
    │     eyJhbGciOiJSUzI1NiJ9.eyJzdWIi...       │
    │                                            │
    │  2. Проверить подпись (через JWKS)         │
    │     ✓ валидна                              │
    │                                            │
    │  3. Проверить exp (не истёк?)              │
    │     ✓ ok                                   │
    │                                            │
    │  4. Извлечь claims (кто user, роли)        │
    │     user = ivan@example.com                │
    │     roles = [USER, ADMIN]                  │
    │                                            │
    │  5. Проверить права (@PreAuthorize)        │
    │     hasRole('USER') → OK                   │
    │                                            │
    │  6. Выполнить бизнес-логику                │
    │     вернуть orders                         │
    └────────────────────────────────────────────┘
                            │
                            │ HTTP Response
                            ▼
    Frontend получает:
    
    HTTP/1.1 200 OK
    Content-Type: application/json
    
    [{"id":1,"product":"Book"}, {"id":2,"product":"Phone"}]
```


## 3. Login — как получить токен в первый раз

**Простая схема login flow**:

```
                    ┌──────────────────┐
                    │      User        │
                    │  (в браузере)    │
                    └────────┬─────────┘
                             │
                    (1) кликает "Login"
                             │
                             ▼
                    ┌──────────────────┐
                    │    Frontend      │
                    └────────┬─────────┘
                             │
                    (2) redirect на Keycloak
                             │
                             ▼
                    ┌──────────────────┐
                    │    Keycloak      │
                    │  показывает      │
                    │  форму login     │
                    └────────┬─────────┘
                             │
                    (3) User вводит login/password
                             │
                             ▼
                    ┌──────────────────┐
                    │    Keycloak      │
                    │  проверяет:      │
                    │  - password ok?  │
                    │  - 2FA?          │
                    └────────┬─────────┘
                             │
                    (4) если ок → создаёт 3 токена:
                             │
                             ▼
              ┌──────────────────────────┐
              │   Keycloak возвращает:   │
              │                          │
              │  ┌─────────────────────┐ │
              │  │ access_token (JWT)  │ │  ← жизнь 15 минут
              │  │ ~500-1000 символов  │ │
              │  └─────────────────────┘ │
              │                          │
              │  ┌─────────────────────┐ │
              │  │ refresh_token       │ │  ← жизнь 7-30 дней
              │  │ ~40-100 символов    │ │
              │  └─────────────────────┘ │
              │                          │
              │  ┌─────────────────────┐ │
              │  │ id_token (JWT)      │ │  ← кто user (OIDC)
              │  │ email, name, etc    │ │
              │  └─────────────────────┘ │
              └──────────────┬───────────┘
                             │
                    (5) redirect обратно на Frontend
                             │
                             ▼
                    ┌──────────────────┐
                    │    Frontend      │
                    │  сохраняет       │
                    │  токены:         │
                    │                  │
                    │  access → memory │
                    │  refresh → cookie│
                    │  (httpOnly)      │
                    └──────────────────┘
                             │
                    (6) готов делать API запросы
                             │
                             ▼
                    ┌──────────────────┐
                    │  User видит      │
                    │  "Добро          │
                    │   пожаловать"    │
                    └──────────────────┘
```


## 4. Access Token и Refresh Token — как работают вместе

**Схема жизни токенов**:

```
    ┌─────────────────────────────────────────────────────────┐
    │              После login у Frontend есть:               │
    │                                                         │
    │   ┌──────────────────────┐    ┌──────────────────────┐  │
    │   │   access token       │    │   refresh token      │  │
    │   │                      │    │                      │  │
    │   │   Живёт: 15 минут    │    │   Живёт: 30 дней     │  │
    │   │   Где: JS memory     │    │   Где: httpOnly cookie│ │
    │   │                      │    │                      │  │
    │   │   Использ. для:      │    │   Использ. для:      │  │
    │   │   каждого API запроса│    │   получить новый     │  │
    │   │                      │    │   access token       │  │
    │   └──────────────────────┘    └──────────────────────┘  │
    │                                                         │
    └─────────────────────────────────────────────────────────┘
```

**Как это работает по времени**:

```
    Время:  0 мин                15 мин            30 мин
    ────────┬──────────────────────┬──────────────────┬────────
            │                      │                  │
            │  Access token жив   │ Access истёк!    │
            │  ← юзер работает     │ Frontend делает  │
            │                      │ refresh          │
            │                      │                  │
            │                      ▼                  │
            │                ┌────────────┐           │
            │                │ Frontend → │           │
            │                │ Keycloak   │           │
            │                │            │           │
            │                │ POST /token│           │
            │                │ refresh_   │           │
            │                │ token=...  │           │
            │                └─────┬──────┘           │
            │                      │                  │
            │                      ▼                  │
            │                Keycloak:                │
            │                - проверяет refresh      │
            │                - выдаёт НОВЫЙ access    │
            │                                         │
            │                Frontend продолжает      │
            │                работать с новым access  │
            │                                         │
            │                                    ...  │
```

**Полная картинка**:

```
    ┌──────────────┐              ┌──────────────┐
    │   Frontend   │              │   Keycloak   │
    └───────┬──────┘              └───────┬──────┘
            │                             │
            │   каждый запрос:            │
            │   Bearer <access>           │
            │                             │
            │  ─── API запрос ──►         │
            │  (без Keycloak!)            │
            │                             │
            │                             │
            │   ─── когда access истёк ──►│
            │        (раз в 15 минут)     │
            │      POST /token            │
            │      refresh_token          │
            │                             │
            │  ◄─── новый access ────     │
            │                             │
            │   продолжаем работать       │
            │                             │
```


## 5. JWT токен — что внутри

**JWT = 3 части через точку**:

```
        xxxxx.yyyyy.zzzzz
        
        header.payload.signature
```

**Реальный пример**:

```
    eyJhbGciOiJSUzI1NiJ9.eyJzdWIiOiJpdmFuIn0.abc123...
    │                    │                    │
    │                    │                    │
    ▼                    ▼                    ▼
    Header               Payload              Signature
    (что за токен)       (данные)             (подпись)
```

**Разберём каждую часть**:

```
    ┌────────────────────────────────────────────┐
    │  Часть 1: HEADER                           │
    │  ─────────────────                         │
    │  (base64 закодированный JSON)              │
    │                                            │
    │  Что внутри:                               │
    │  {                                         │
    │    "alg": "RS256",     ← алгоритм подписи  │
    │    "kid": "abc123"     ← ID ключа          │
    │  }                                         │
    │                                            │
    │  Для чего: как проверять подпись           │
    └────────────────────────────────────────────┘
                          │
                          ▼
    ┌────────────────────────────────────────────┐
    │  Часть 2: PAYLOAD (данные)                 │
    │  ─────────────────                         │
    │  (base64 закодированный JSON)              │
    │                                            │
    │  Что внутри:                               │
    │  {                                         │
    │    "sub": "user-uuid-123",  ← кто user     │
    │    "email": "ivan@ex.com",                 │
    │    "name": "Иван Иванов",                  │
    │    "roles": ["ADMIN", "USER"],             │
    │    "iat": 1712345000,       ← выдан        │
    │    "exp": 1712345678        ← истечёт      │
    │  }                                         │
    │                                            │
    │  Для чего: сама информация о user          │
    │                                            │
    │  ⚠ ВАЖНО: НЕ шифруется! Любой может       │
    │  прочитать. Только защищена от подделки.   │
    │  Нельзя класть пароли или карты!           │
    └────────────────────────────────────────────┘
                          │
                          ▼
    ┌────────────────────────────────────────────┐
    │  Часть 3: SIGNATURE (подпись)              │
    │  ─────────────────                         │
    │                                            │
    │  Что это:                                  │
    │  Keycloak берёт header + payload и         │
    │  подписывает их приватным ключом (RSA).    │
    │                                            │
    │  signature = RSA_sign(                     │
    │    private_key,                            │
    │    header + "." + payload                  │
    │  )                                         │
    │                                            │
    │  Для чего:                                 │
    │  - Backend проверяет подпись public key    │
    │  - Если payload изменили → подпись битая   │
    │  - Только Keycloak может подписать         │
    │    (только у него private key)             │
    └────────────────────────────────────────────┘
```

**Как Backend проверяет JWT**:

```
    Backend получил JWT
             │
             ▼
    ┌──────────────────────────────┐
    │  Шаг 1: Разобрать на 3 части │
    │  header.payload.signature    │
    └──────────────┬───────────────┘
                   │
                   ▼
    ┌──────────────────────────────┐
    │  Шаг 2: Взять public key     │
    │  из Keycloak /jwks           │
    │  (кэшируется, забирается 1   │
    │   раз, обновляется редко)    │
    └──────────────┬───────────────┘
                   │
                   ▼
    ┌──────────────────────────────┐
    │  Шаг 3: Проверить подпись    │
    │  RSA_verify(public_key,      │
    │    header+payload,           │
    │    signature)                │
    │                              │
    │  ✓ ok → payload не подделан  │
    │  ✗ fail → отвергаем токен    │
    └──────────────┬───────────────┘
                   │
                   ▼
    ┌──────────────────────────────┐
    │  Шаг 4: Проверить claims     │
    │  - exp > now? (не истёк?)    │
    │  - iss == expected?          │
    │  - aud == мой client?        │
    └──────────────┬───────────────┘
                   │
                   ▼
    ┌──────────────────────────────┐
    │  Шаг 5: Извлечь user info    │
    │  sub = "user-uuid-123"       │
    │  roles = [ADMIN, USER]       │
    └──────────────────────────────┘
```

```
    ┌──────────────────┐
    │      User        │
    │  вставил USB     │
    │  с ЭЦП           │
    └────────┬─────────┘
             │
             ▼
    ┌──────────────────┐        ┌──────────────────┐
    │    Browser       │◄───────│    NCALayer      │
    │                  │        │  (программа на   │
    │  жмёт "Войти     │        │   компе user'а)  │
    │   через ЭЦП"     │        │                  │
    └────────┬─────────┘        │  умеет работать  │
             │                  │  с USB-токенами  │
             │                  └──────────────────┘
             │                            ▲
             │                            │
             │  (Browser просит NCALayer  │
             │   подписать данные)        │
             └────────────────────────────┘
                        │
                        ▼
            ┌────────────────────────┐
            │  NCALayer:             │
            │  - спрашивает PIN      │
            │  - читает USB-токен    │
            │  - подписывает данные  │
            │    приватным ключом    │
            │  - возвращает подпись  │
            │    + X.509 cert        │
            └────────────┬───────────┘
                         │
                         ▼
            ┌────────────────────────┐
            │  Browser отправляет:   │
            │  - подпись             │
            │  - сертификат          │
            │  на Keycloak           │
            └────────────┬───────────┘
                         │
                         ▼
            ┌────────────────────────┐
            │  Keycloak проверяет:   │
            │  - подпись через       │
            │    public key из cert  │
            │  - цепочку доверия     │
            │    (казахстанский CA)  │
            │  - не отозван?         │
            │                        │
            │  Извлекает из cert:    │
            │  - ИИН                 │
            │  - ФИО                 │
            │                        │
            │  Выдаёт JWT токен      │
            └────────────────────────┘
```

**Что внутри JWT после ЭЦП login**:

```
    {
      "sub": "user-uuid",
      "iin": "800101300123",        ← извлечён из сертификата
      "name": "Иван Иванов",
      "roles": [...],
      ...
    }
```


## 7. Что где хранится физически

```
    ═══════════════════════════════════════════════
                    FRONTEND
    ═══════════════════════════════════════════════
    
    ┌────────────────────────────────────────┐
    │  Access token:                         │
    │  → JavaScript memory (переменная)      │
    │  ← защищено от XSS                     │
    │  ← НЕ в localStorage!                  │
    │  ← живёт до перезагрузки страницы      │
    └────────────────────────────────────────┘
    
    ┌────────────────────────────────────────┐
    │  Refresh token:                        │
    │  → httpOnly cookie                     │
    │  ← JS не может прочитать               │
    │  ← защищено от XSS                     │
    │  ← автоматически шлётся браузером      │
    └────────────────────────────────────────┘
    
    ═══════════════════════════════════════════════
                    BACKEND
    ═══════════════════════════════════════════════
    
    ┌────────────────────────────────────────┐
    │  НЕ хранит токены!                     │
    │  Только проверяет их при запросах.     │
    │                                        │
    │  Кэширует:                             │
    │  - Public keys (JWKS) — обновляется    │
    │    редко                               │
    └────────────────────────────────────────┘
    
    ═══════════════════════════════════════════════
                    KEYCLOAK (свой PostgreSQL)
    ═══════════════════════════════════════════════
    
    ┌────────────────────────────────────────┐
    │  - Users (email, password hash)        │
    │  - Clients (client_id, secret)         │
    │  - Roles                               │
    │  - Sessions (кто залогинен)            │
    │  - Private key (для подписи JWT)       │
    │  - Public key (отдаётся через /jwks)   │
    │  - Логи всех login events              │
    └────────────────────────────────────────┘
```


## Что запомнить

**HTTP запрос с токеном**:
- Токен идёт в header: `Authorization: Bearer <JWT>`
- Backend извлекает, проверяет подпись, проверяет claims.
- НЕ ходит в Keycloak (проверка локальная).

**Login flow**:
1. User → Frontend → Keycloak (redirect)
2. Keycloak показывает форму
3. User вводит password
4. Keycloak возвращает 3 токена: access, refresh, id
5. Frontend сохраняет: access в memory, refresh в cookie

**Access + Refresh**:
- **Access** — короткий (15 мин), для API запросов.
- **Refresh** — долгий (30 дней), для получения новых access.
- Когда access истекает → Frontend делает refresh → получает новый access.

**JWT = 3 части**:
1. **Header** — какой алгоритм подписи.
2. **Payload** — данные о user (email, roles, exp).
3. **Signature** — подпись Keycloak (защита от подделки).

**Проверка JWT**:
- Backend один раз забрал public key из /jwks.
- Каждый запрос — проверка локальная (быстро).
- Если подпись валидна и exp не истёк → доверяем.

**ЭЦП** (Казахстан):
- User имеет USB-токен с приватным ключом.
- NCALayer подписывает данные.
- Keycloak проверяет через public key из X.509 сертификата.
- Извлекает ИИН из сертификата.
